# Fix H1 + H2: privilege validation for the monitor user

## Context

Both high findings from [REVIEW_FINDINGS.md](REVIEW_FINDINGS.md) share one root cause, verified against source and MySQL/MariaDB docs: **nothing validates that the monitor user has the privileges the collector's queries depend on**, even though README.md:95-107 documents them. Two silent failure modes follow:

- **H1** — without `PROCESS`, `COUNT(*)` over `information_schema.PROCESSLIST` (facts.go:44) can't see the replication user's binlog-dump threads, returns 0 *successfully*, and `/health/primary` 503s forever (write outage via HAProxy `fall 1 inter 500ms`).
- **H2** — without `REPLICA MONITOR`/`REPLICATION CLIENT`, `SHOW REPLICA STATUS` fails with 1227, which is not 1064 so the `SHOW SLAVE STATUS` fallback never fires (facts.go:119), and every request 503s with a raw driver error.

Verified caveats that shape this fix: the doc's proposed `SHOW GRANTS` substring check is flawed (misses `GRANT ALL PRIVILEGES`; `SHOW GRANTS` returns multiple rows for dynamic privileges), and a fatal startup check conflicts with main.go:52-54's deliberate "sidecar may start before the database" design. Per your choices: **warn only** (connections recycle ≤5 min via `ConnMaxLifetime`, so grants fixed later self-heal without restart) and **go-sqlmock** for tests.

## Changes

### 1. New file `internal/mysql/preflight.go`

`func (c *Collector) CheckPrivileges(ctx context.Context) error` — reuses the existing `replicaStatus` method (gets the 1064→`SHOW SLAVE STATUS` fallback for free, and warms the `replicaStmt` cache) and the `isMySQLError` helper:

1. **H2 probe (behavioral):** `c.replicaStatus(ctx)` — on `1227` return a clear error: monitor user cannot read replication status; needs `REPLICA MONITOR` (MySQL 8.0.22+ / MariaDB 10.5+) or `REPLICATION CLIENT` (older servers), with the `GRANT ... ON *.*` hint. Other errors pass through wrapped. A `(nil, nil)` result (node isn't a replica) means privileges are fine.
2. **H1 check (grant scan):** iterate ALL rows of `SHOW GRANTS FOR CURRENT_USER()` (not `QueryRow` — dynamic privileges get their own row); fail with a remediation error unless some row contains `PROCESS` or `ALL PRIVILEGES` (uppercased match). Comment the known limitation: privileges granted only via roles won't be seen here — that gap is covered by the runtime warning below.

### 2. `internal/mysql/facts.go` — hot-path diagnosis (covers DB-unreachable-at-boot, when the startup preflight is skipped)

- Extract a small shared helper that wraps the `replicaStatus` error, appending the same remediation text when `isMySQLError(err, 1227)`; use it in both `CheckPrivileges` and `Facts` (facts.go:71-74). This fixes "diagnosis requires reading the raw MySQL error" at the source — every 503 now carries the hint.
- One-shot runtime warning for H1, mirroring the existing `superROUnknownLog.CompareAndSwap` idiom (facts.go:104): new `atomic.Bool` field; after a successful collect, when `ConnectedReplicas == 0 && !ReadOnly && !SuperReadOnly && !ReplicaConfigured`, log once: writable non-replica server reports 0 connected replicas — if replicas should be connected, the monitor user likely lacks `PROCESS` and cannot see their binlog-dump threads (link README section). `atomic.Bool` needs no init in `NewCollector`.

### 3. `main.go` — one call site

- Hoist `mysql.NewCollector(db, cfg.QueryTimeout)` out of the `httpserver.New(...)` inline expression into a `collector` variable (used for both preflight and handler — no behavior change).
- Inside the existing ping-success branch (main.go:55-57), after `"database reachable"`, run `collector.CheckPrivileges` with a `cfg.QueryTimeout`-bounded context; on error log `myhealthz: WARNING: monitor user privileges incomplete: %v` (non-fatal). In the ping-failure branch, extend the existing warning to note the privilege check was skipped (hot-path errors will diagnose once reachable).

### 4. `README.md`

One sentence in "Required database privileges": myhealthz validates these once at startup when the database is reachable (and per-request otherwise) and logs remediation hints; missing grants surface as 503s with the same hint.

### 5. Tests — `internal/mysql/preflight_test.go` + go-sqlmock

Add `github.com/DATA-DOG/go-sqlmock` as the only test dependency. Ordered-expectation cases:

- Happy path: `SHOW REPLICA STATUS` row present (MariaDB-style columns) + grants row containing `PROCESS` → nil error.
- H2: `SHOW REPLICA STATUS` → 1227 → error names both privileges; **assert no `SHOW SLAVE STATUS` query was issued** (fallback must not fire on 1227).
- Fallback preserved: `SHOW REPLICA STATUS` → 1064 → `SHOW SLAVE STATUS` succeeds → check continues to grants.
- H1: grants rows (multi-row, testing the `QueryRow` regression) without `PROCESS`/`ALL PRIVILEGES` → PROCESS remediation error; second-row `PROCESS` → nil.
- `Facts` 1227 → wrapped error contains the hint.
- One-shot warning fires exactly once across two `Facts` calls (capture via `log.SetOutput`), and not at all when replicas connected / read-only / replica-configured.

### Not in scope

M6 (stop returning raw errors to clients), M1 (caching/performance_schema), H3, and any edits to REVIEW_FINDINGS.md (left as the review artifact; the commit records the fix).
