# myhealthz — MySQL/MariaDB health check server (Go) + podman demo

## Context

A load balancer (HAProxy) routing MySQL traffic needs to know which DB node is the **primary** (accept writes) and which are **replicas** (serve reads). `myhealthz` is a tiny Go sidecar exposing HTTP endpoints that answer exactly that question, so HAProxy `http-check`s can gate write/read backends. It works against both MySQL and MariaDB, discovers how to connect (socket → localhost:3306 → CLI args, **args override** per user decision; TLS optional), and ships with a podman demo: 3 MariaDB replicas + HAProxy with a scripted switchover.

Facts confirmed during exploration that shape the design:
- MariaDB does **not** have `super_read_only` (unknown-variable error; MariaDB `read_only` already blocks SUPER users) → query it defensively, treat failure as "unsupported → 0".
- MariaDB `SHOW REPLICA STATUS` (10.5.1+) returns old `Master_*`/`Slave_*` columns; MySQL 8.0.22+ returns `Source_*`/`Replica_*` → parse by **column name**, accept both families; fall back to `SHOW SLAVE STATUS` on syntax error (old MySQL/MariaDB).
- Connected replicas appear in the processlist as `COMMAND LIKE 'Binlog Dump%'` on both servers.
- Host: Go 1.26.8, podman 5.4.2 rootless (amd64), `mariadb:11.8` image already local, MariaDB client on host. Module convention: `github.com/sriharip316/myhealthz`, `go 1.26.0`.

## Role definitions (implemented as pure logic)

- **Primary** = `read_only=0` AND `super_read_only=0` AND **no** replica configuration (empty `SHOW REPLICA/SLAVE STATUS`) AND connected-replica count ≥ `-min-replicas` (default 1).
- **Replica** = (`read_only=1` OR `super_read_only=1`) AND replica configured AND IO thread = Yes AND SQL thread = Yes AND (lag ≤ `-max-lag`, default disabled).
- A node with replica config but stopped threads is **neither** (503 on both endpoints) — the safe HA behavior during switchover.

## Implementation details

**Connection priority** (`endpoint.go`): if `-host` or `-socket` given → use directly (socket arg → unix DSN; host arg → tcp). Otherwise probe in order (300ms dial probe each): `$MYSQL_UNIX_PORT`, `/var/run/mysqld/mysqld.sock`, `/run/mysqld/mysqld.sock`, `/run/mysql/mysql.sock`, `/tmp/mysql.sock`, `/var/lib/mysql/mysql.sock` → first live socket wins; else `tcp(127.0.0.1:3306)`. Log the chosen endpoint at startup.

**Flags**: `-listen :8080`, `-host`, `-port 3306`, `-socket`, `-user root`, `-password`, `-password-file`, `-min-replicas 1`, `-max-lag -1` (disabled), `-connect-timeout 3s`, `-query-timeout 2s`, `-tls false|true|skip-verify`, `-tls-ca-file`, `-tls-server-name`, `-tls-cert-file`, `-tls-key-file`. TLS applies to TCP only.

**Facts collection** (`facts.go`, per request, small conn pool):
- `SELECT @@read_only` always; `SELECT @@super_read_only` separately, error → 0 (MariaDB), log once.
- `SHOW REPLICA STATUS`; on syntax error (errno 1064) fall back to `SHOW SLAVE STATUS` (choice cached). Scan rows into map keyed by lowercased column name; read keys from both families: `master_host|source_host`, `slave_io_running|replica_io_running`, `slave_sql_running|replica_sql_running`, `seconds_behind_master|seconds_behind_source`. No row → not configured as replica.
- `SELECT COUNT(*) FROM information_schema.PROCESSLIST WHERE COMMAND LIKE 'Binlog Dump%'` → connected replicas.

**HTTP** (`server.go`): 200/503 + JSON body on `/health/primary` and `/health/replica`; bonus endpoints: `/status` (full facts, always 200), `/healthz` (liveness), `/` (index). DB error → 503 with error in JSON. Log role transitions. Graceful shutdown on SIGTERM.

**Unit tests**:
- `endpoint_test.go`: priority/override logic; real unix socket via `net.Listen` in temp dir for discovery probing.
- `facts_test.go`: replica-status column mapping for both MariaDB-style and MySQL-style columns (pure parse function).
- `decision_test.go`: table-driven primary/replica/neither cases incl. min-replicas and lag.
- `server_test.go`: httptest with fake Facts provider → status codes + JSON.

## Demo (podman E2E)

- Network `mhnet`; containers `db1/db2/db3` = `docker.io/library/mariadb:11.8` (local) with `--server-id=N --log-bin --gtid-strict-mode=1 --gtid-domain-id=N`; host ports `1306N:3306` + `1808N:8080`.
- Sidecars `healthN`: `podman run -d --name healthN --network container:dbN localhost/myhealthz:dev -listen :8080 -user myhealthz -password ...` — connect via **localhost:3306 auto-discovery** (priority 2 in action); HAProxy reaches them at `dbN:8080`.
- Users created once on db1 (replicate to db2/db3 via binlog): `repl` (`REPLICATION SLAVE`), `myhealthz` (`REPLICATION CLIENT, PROCESS`). db2/db3: `CHANGE MASTER TO MASTER_HOST='db1' ... MASTER_USE_GTID=Slave_pos; START SLAVE; SET GLOBAL read_only=1` (+ best-effort `super_read_only` for MySQL compat).
- `haproxy.cfg`: `mysql-write` (3307, http-check `/health/primary`, `on-marked-down shutdown-sessions`), `mysql-read` (3308, `balance leastconn`, http-check `/health/replica`), stats page :9000; host ports 13307/13308/19080.
- `demo.sh switchover`: db1 `read_only=1` → db2 `STOP SLAVE; read_only=0; RESET SLAVE ALL` → (window where write backend has no healthy node — narrated, split-brain-safe) → db3 `CHANGE MASTER TO MASTER_HOST='db2' ...; START SLAVE` → wait for db2 `/health/primary` 200 → repoint db1 as replica of db2. 
- `demo.sh verify`: scripted E2E — asserts endpoint codes and, via host MariaDB client through HAProxy ports, that writes hit db1 before / db2 after switchover and reads only hit replicas; exits non-zero on failure.
- `status` shows per-node `/status` output, HAProxy routing checks, stats URL; `teardown` removes everything.
